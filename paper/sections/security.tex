\section{Threat Model and Privacy Mechanisms}
\label{sec:security}

\subsection{Threat model}
We consider an honest-but-curious aggregator and a passive eavesdropper on the uplink, both of whom observe exactly the bytes a site transmits in each round: the broadcast state and the site's returned slice of the active tiers. Neither party observes the private head, local data or local optimiser state. We do not consider Byzantine participants or model poisoning. The attack surface of a method is therefore the sequence of slices it transmits, and we measure it in three ways on every method.

\subsection{Update inversion}
The adversary reconstructs a batch $\hat x$ from an observed update $\Delta_{\mathcal A}$ restricted to the transmitted tiers by solving
\begin{equation}
\hat x=\arg\min_x\ 1-\cos\!\Big(\nabla_{\theta_{\mathcal A}}\ell\big(h_\theta(x),y\big),\ -\Delta_{\mathcal A}\Big),
\label{eq:inv}
\end{equation}
the cosine objective of Geiping \emph{et al.}~\cite{geiping2020} without an image prior, since the inputs are tabular. Unlike a single-batch gradient attack~\cite{zhu2019dlg}, the observed update is the result of a full local epoch of Adam steps, which is the update an aggregator actually sees; this is the update-inversion setting of~\cite{geiping2020}. The attack is run inside training, on the first site's real transmitted slice, in every round in which that site transmits, for every method, so a method that transmits rarely is attacked on the rounds in which it does. Success is the normalised reconstruction error and the feature correlation between each true row and its best-matching reconstruction; lower correlation means a smaller attack surface. The attack is intentionally generic: the aim is a like-for-like comparison of what each method exposes, not the strongest possible adversary.

\subsection{Membership inference}
Against the deployed (personalised) model of every site we run the loss-threshold attack of Yeom \emph{et al.}~\cite{yeom2018}: the adversary labels a record a training member when the model's loss on it is low. The attack AUC over members and patient-grouped non-members, averaged over sites, measures memorisation of the released model; $0.5$ is no leakage.

\subsection{Client-level differential privacy}
\label{sec:security-dp}
Each round, every site joins the cohort $\mathcal S_r$ independently with probability $q$ (Poisson sampling; $q=1$ is full participation). The server clips every participating site's returned delta and adds noise to the sum before dividing by the \emph{fixed} expected cohort size:
\begin{equation}
\tilde\Delta=\frac1{qN}\Big(\sum_{k\in\mathcal S_r}\Delta_k\min\big(1,\tfrac{C}{\|\Delta_k\|_2}\big)+\mathcal N(0,\sigma^2C^2I)\Big),
\label{eq:dp}
\end{equation}
the fixed-denominator DP-FedAvg estimator of McMahan \emph{et al.}~\cite{mcmahan2018dp}, so that adding or removing one site changes the sum by at most $C$ in $\ell_2$ and the denominator reveals nothing about the realised cohort. A planned release whose cohort happens to be empty still adds noise. The mechanism is applied by the server to every method identically. The accountant composes, over the $R_{\mathrm{tx}}$ planned releases, the R\'enyi DP of the Poisson-subsampled Gaussian mechanism at integer orders~\cite{mironov2019sgm},
\begin{equation}
\varepsilon_\alpha=\frac{R_{\mathrm{tx}}}{\alpha-1}\log\sum_{k=0}^{\alpha}\binom{\alpha}{k}(1-q)^{\alpha-k}q^k e^{\frac{k^2-k}{2\sigma^2}},\qquad
\varepsilon=\min_{\alpha}\Big\{\varepsilon_\alpha+\frac{\log(1/\delta)}{\alpha-1}\Big\},
\label{eq:rdp}
\end{equation}
with $\delta=10^{-5}$; for $q=1$ this reduces to $R_{\mathrm{tx}}\alpha/(2\sigma^2)$~\cite{mironov2017}. The implementation reproduces the reference value of the TensorFlow-Privacy MNIST tutorial ($q=256/60000$, $\sigma=1.1$, 60 epochs, $\varepsilon\approx3.0$) and the $q=1$ closed form; both are unit tests. For a matched-privacy comparison every method is given the same target $\varepsilon^\star$ and $\sigma$ is calibrated, by bisection on (\ref{eq:rdp}), to that method's own release count.

\textbf{Which schedules are covered.} The accountant covers a release only if the decision to release is independent of the private data. This holds for FedAvg, FedProx, FedPer, the fixed period and \tierfed{}-DP, whose release rounds are fixed before training. It does not hold for adaptive \tierfed{}, AdaComm, LAG or FedLAMA: their schedules are functions of client updates or losses, so the release pattern leaks information that (\ref{eq:rdp}) does not charge for. The released code refuses to run these strategies under DP (an explicit override exists only to reproduce the earlier table). The earlier version of this article compared all methods at equal $\sigma$ including the adaptive ones; that comparison is formally not covered by its stated budgets, is moved to the Supplement (Section~S3) with this caveat, and is superseded by the matched-$\varepsilon$ comparison in Section~\ref{sec:results-privacy}. Earlier still, the aggregate rather than each site's delta was clipped; that mechanism does not bound the sensitivity to one site. The budgets reported are as computed; with $N=20$ sites, client-level budgets in the range we test are weak guarantees, and we claim only that the trade-off is measured correctly.
